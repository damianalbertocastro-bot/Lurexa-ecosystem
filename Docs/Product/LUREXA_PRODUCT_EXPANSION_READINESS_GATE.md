# Lurexa Product Expansion Readiness Gate

Status: Phase 20 contract implemented

This gate must pass before substantial standalone Insight, Studio or Campus functionality is expanded.

## Core/Mind/Product boundaries

- Core owns identity, authorization, trusted records, persistence and provenance.
- Mind interprets authorized learning evidence and executes governed learning-intelligence tasks.
- Products own experience delivery and generate evidence.
- Campus is an institutional orchestration shell, structurally distinct from the six sibling products.

## Insight

Before standalone runtime expansion: define institutional/cohort aggregation contracts; define privacy thresholds and purpose scopes; keep learner-level instructional actions inside Learn; require server-owned organization authorization.

## Studio

Before standalone authoring expansion: define Knowledge Object versioning; define provenance, review, approval and publication states; persist authoritative objects through governed Core services; prevent local prototype state from being presented as published truth.

## Campus

Before standalone institutional runtime expansion: resolve authenticated tenant identity through Core; project organization roles and capabilities server-side; use Product Bridge only as scoped, expiring navigation context; do not treat Campus as a seventh product owner.

## Universal release gates

Every expanded product requires protected CI, type/lint/build validation, server-side authorization and cross-tenant tests, observability and redaction, accessibility validation, deployment topology validation, product-specific runtime acceptance, and explicit maturity promotion evidence.

Marketplace remains deferred until server-owned commerce, entitlement, publisher/payout, refund/dispute and audit architecture exists.
